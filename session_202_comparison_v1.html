01 / Lab findings

เทียบ 3 เจ้า จากการใช้งานจริงของทีม

สรุปจากการลองใช้จริงใน lab ไม่ใช่จาก spec sheet — รอบนี้ใช้ Cursor เป็นตัวหลัก

Cursor — เครื่องมือหลักที่ทดลอง

ทำได้ดี
  • Automation & Workflow: ทำ pipeline automation ของ development task ได้ง่าย ดูสถานะและจัดการ sub-agent ระหว่างสั่งงานได้ดี
  • Plan Mode ให้ workflow ที่เข้าใจง่าย, Ask Mode ถามกลับเมื่อ agent ไม่แน่ใจ และมี built-in doc ให้ agent อ้างอิง
  • Multi-model review: สั่งหลาย model รีวิวโค้ดพร้อมกันแล้วทำ majority vote ได้
  • Team & Enterprise: Team Rules บังคับ coding standard ทั้งทีม, ตั้ง spend alert/limit ง่าย, dashboard analytics ครบ, เห็น usage รายคนละเอียด
  • Audit & Traceability: ดู Agent Line of Code ได้ใน metric และ audit log บอกว่าใครทำอะไร เช่น เพิ่ม MCP
  • เสถียร: native desktop app และการแจ้งเตือนแบบ native ใช้ได้ดี พร้อม Cloud Sandbox ที่ควบคุมผ่าน UI ได้
ข้อจำกัดที่เจอ
  • ไม่มี mode Co-work — ผูกกับ repository เน้น code เป็นหลัก เหมาะกับ Developer & SE มากกว่า end user
  • Microsoft extension ไม่ครบเท่า VS Code: ขาด Azure Functions (deploy Function App / list resource) ส่วน C# Dev Kit มีแต่ไม่ใช่ official และบางครั้ง conflict กับ extension อื่น
  • Cloud Agent ยังไม่ native support Azure DevOps repository (กำลัง explore เพิ่มเติม)
  • ต้องใช้เวลา research + config เพิ่ม ถ้าจะใช้ Cloud Agents เต็มรูปแบบ

GitHub Copilot — ข้อสังเกตจากการใช้

  • Crash บ่อยเมื่อเจอ task ขนาดใหญ่
  • จุดแข็งคือความเข้ากับ VS Code / GitHub / Azure ดูรายละเอียดในตาราง 02

Claude — ข้อสังเกตจากการใช้

  • Co-work เกิด crash ในบางกรณี เช่น งานที่ไล่ step 1, 2, 3 ต่อเนื่อง
  • เด่นเรื่องแชร์ context ระหว่างทีม technical กับ business — เป็นคนละกลุ่มกับ IDE assistant
02 / Key metrics

Key Metrics: เทียบฟีเจอร์หลักจากมุม GitHub Copilot

ใช้ฟีเจอร์ของ GitHub Copilot เป็นจุดอ้างอิง — ทุกช่องแสดงสถานะจริงของแต่ละเจ้า อ้างอิงจาก official docs ตามเลข [n]

Baseline จุดอ้างอิงในการเทียบ — ไม่ได้แปลว่าดีกว่า มี รองรับเต็มรูปแบบ บางส่วน มีแต่ขอบเขตจำกัด ไม่มี ไม่อยู่ในขอบเขตผลิตภัณฑ์ จุดแข็ง เจ้าที่เด่นที่สุดในแถวนั้น เส้นประ = Claude อยู่อีกกลุ่ม (Co-work) แต่เทียบร่วมในตาราง

Inline Code Completionเติมโค้ด inline ขณะพิมพ์ใน IDE มีจุดแข็งดั้งเดิม adoption สูงใน VS Code และ Visual Studio มีTab model เร็ว คาดเดาการแก้แบบ multi-line ได้ดี ไม่มีไม่มี inline completion ใน IDE ต้องใช้ Claude Code/chat แทน

Open-source IDE BaseLicense เสียบกับ editor ฟรีได้ ไม่ผูกกับ IDE เฉพาะ มีจุดแข็งVS Code เป็น open source ใช้ฟรี — Copilot เป็น extension เสียบเข้า editor เดิม ถ้าหยุดจ่าย license ยังใช้ VS Code เขียนโค้ดต่อได้[10] ไม่มีเป็น proprietary fork ของ VS Code ต้องใช้ IDE ของ Cursor เอง — มี Hobby plan ฟรีแบบจำกัด แต่ใช้งานจริงต้องซื้อ subscription และถ้าเลิกใช้ต้องย้าย editor[11] มีไม่มี IDE ของตัวเอง — ใช้ license ผ่าน Claude Code extension/CLI บน VS Code, JetBrains หรือ terminal ได้[8]
Coding Agent (Issue → PR)มอบหมายงานจาก GitHub ให้ AI สร้าง PR มีAssign GitHub Issue ให้ cloud agent สร้าง branch/PR ใน GitHub Actions[4] มีสั่ง Cloud Agent ได้จาก @cursor ใน GitHub issue/PR, Slack, Linear และ web[2] บางส่วน@claude ผ่าน GitHub Actions ได้ แต่ค่า default push branch แล้วให้คนเปิด PR เอง[8]
Scheduled Automationตั้งเวลา/ตั้ง trigger ให้ agent ทำงานเองอัตโนมัติ บางส่วนไม่มี scheduler ในตัว Copilot — ตั้งเวลาได้ผ่าน GitHub Actions cron แล้วเขียน workflow เรียก agent เอง[20] มีจุดแข็งAutomations: ตั้ง cron หรือ trigger จาก GitHub/Slack/Linear/PagerDuty/webhook ผ่าน UI ได้เลย ไม่ต้องเขียน workflow[19] บางส่วนตั้ง schedule ผ่าน claude-code-action + Actions cron ได้ แต่ต้องเขียน workflow เอง[8]
Sandboxed Executionรันคำสั่งใน sandbox ที่ผู้ใช้กำหนดขอบเขตและเข้าควบคุมได้ บางส่วนCloud agent รันใน GitHub Actions แบบ ephemeral + firewall ปรับผ่าน setup file ได้ แต่เข้าไปควบคุมเครื่องระหว่างรันไม่ได้[4] มีจุดแข็งSandbox ระดับ OS ในเครื่อง คุม filesystem/network เองได้ผ่าน sandbox.json + allowlist และ takeover remote desktop ของ cloud agent ได้[1][2] บางส่วน/sandbox ใน Claude Code แยก filesystem/network ได้ดี แต่เป็น opt-in และครอบเฉพาะ Bash tool[7]
Code Review on PRsReview PR อัตโนมัติใน Git workflow มีCopilot code review ฝังใน GitHub PR flow ไม่ต้องออกจาก toolchain มีBugBot comment inline ใน GitHub PR + check + Autofix[3] บางส่วนทำ auto review ผ่าน claude-code-action ได้ แต่ต้อง setup Actions เอง[8]
GitHub / Azure Integrationผูก VS Code, GitHub.com, Azure DevOps และ Entra มีจุดแข็งNative ทั้ง Microsoft stack ตรงกับ GULF ที่ใช้ GitHub + Azure[4] บางส่วนมี GitHub integration (BugBot, @cursor) แต่ Azure DevOps ยังต้อง pilot จริง บางส่วนเชื่อมผ่าน Actions/MCP ได้ แต่ไม่ native กับ Microsoft governance
Model Choiceเลือก model ได้ตาม task มีเลือก GPT / Claude / Gemini ใน model picker ขึ้นกับ plan (Pro+/Business/Enterprise)[5] มีสลับหลาย model ใน IDE เดียว ไม่ผูกกับ vendor ใดรายเดียว ไม่มีใช้ Anthropic models เท่านั้น ไม่ multi-vendor
Codebase Vector Index & Semantic Searchทำ index โค้ดเป็น vector แล้วค้นหาเชิงความหมายได้ มีRemote semantic index สร้างโดย GitHub อัตโนมัติสำหรับ repo บน GitHub/Azure DevOps ส่วน local index จำกัด ~2,500 ไฟล์[12] มีจุดแข็งIndex ลึกสุด: tree-sitter chunking + custom embedding + vector DB, sync อัตโนมัติทุก 5 นาที, encrypt path และไม่เก็บ source code บน server[13] ไม่มีClaude Code เลือกไม่ทำ index โดยตั้งใจ ใช้ agentic search (grep/glob) — Anthropic ให้เหตุผลเรื่องความสดของข้อมูลและ security[14]
Org Knowledge & Context SharingKnowledge base และการแชร์ context ระดับองค์กร มีCopilot Spaces + extensions ใน GitHub ecosystem[6] มีTeam Rules ตั้ง rule/มาตรฐานระดับองค์กรจาก dashboard ใช้กับทุกคนทุก repo และ enforce ไม่ให้ปิดได้ — รูปแบบเป็น rules ต่างจาก Spaces ที่เป็นพื้นที่แชร์ไฟล์/โค้ด[15] บางส่วนจุดแข็งProjects แชร์ context ข้ามทีม business + dev ได้ดีที่สุดในมุม Co-work แต่ไม่ใช่ dev extension model
Enterprise GovernanceSSO, policy, audit ระดับองค์กร มีGitHub Enterprise + Microsoft Entra SSO + policy/audit ตรง stack เดิมของ GULF บางส่วนมี SSO/SCIM, Privacy Mode และคุม sandbox/allowlist ผ่าน MDM ได้ แต่ไม่ align GitHub Enterprise governance เต็มรูป[1] มีClaude Enterprise มี SAML/OIDC SSO, SCIM, audit log + Compliance API (เก็บ activity 6 ปี) แต่อยู่นอก Microsoft stack[9]

หมายเหตุแถว Vector Index: จาก research ของ Cursor เอง semantic search เพิ่มความแม่นยำราว 12.5% เทียบกับใช้ grep อย่างเดียว และเห็นผลชัดใน repo ขนาด 1,000+ ไฟล์[13] — ยังไม่พบหลักฐานอิสระว่าความต่างในงานจริง significant มาก ฝั่ง Anthropic เองยืนยันว่า agentic search ทำงานได้ดีโดยไม่ต้องมี index[14] จึงควรพิสูจน์ด้วย pilot กับ repo จริงของ GULF

Take aways

  1. 1Copilot กับ Cursor คะแนนใกล้กันมาก — Copilot ชนะด้วย ecosystem/Microsoft fit ส่วน Cursor ชนะจากการใช้จริงเรื่อง automation, sandbox และการคุม agent
  2. 2Claude เป็นอีกกลุ่ม (Co-work) — ใช้เสริมงานข้ามทีม ไม่ใช่ตัวแทน IDE assistant
  3. 3Privacy & IP ต้องปิดก่อน rollout: ทุกเจ้าทำ no-training/ZDR ได้ แต่ indemnification ต่างกัน — Copilot ผูกเงื่อนไข filter/tier, Cursor ต้องต่อรองในสัญญา, Claude มีแบบจำกัด cap[16][17][18]
  4. 4Hybrid 3 เจ้ามีต้นทุนแฝง (สัญญา + security review หลายรอบ) — เริ่ม 2 เจ้าพร้อม central policy และโครงสร้างราคายังไม่ได้รีวิว ต้องทำ TCO แยกอีกฉบับ

Lab รอบถัดไป

  • Privacy & IP (priority แรก): เปิด Privacy Mode/ZDR จริง + trace data flow ของ cloud agent
  • Benchmark กับ repo C#/.NET และ Azure Cosmos DB จริงของ GULF
  • ทดสอบ Azure DevOps integration ที่ยังเป็นคอขวดของ Cursor
  • ลอง Scheduled Automation จริง: Cursor Automations เทียบ GitHub Actions cron
